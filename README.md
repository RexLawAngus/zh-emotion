# zh-emotion · 中文情绪分析

用“手法—内容—效果／情感”的答题式结构，分析中文单句、多轮对话和篇章中的情绪，为阅读、研究和后续模型行动提供可追溯的依据。建议结合stop-slop进行使用（https://github.com/hardikpandya/stop-slop）。

## 状态与版本

这是 `zh-emotion` 的首个版本，**1.0.0**。作者选择 MIT 许可证，见 [LICENSE](LICENSE)。

这是提示词与参考资料组成的 skill，不附带模型权重，不调用外部 API，也不会自动收集数据。宿主模型和运行环境决定实际能力、数据处理方式与费用。默认输出分析卡，按需提供 JSON。

## 能做什么

- 自然对话、工作沟通、社交媒体及文学等中文语境中的情绪解读。
- 区分情绪主体、对象、直接自述、叙述描写和语境推断。
- 分析混合情绪、反讽候选解释及上下文中的延续和转折。
- 保留原文依据、替代解释与信息缺口，供研究者或下游模型复核。

不保证识别主体真实内心；不提供已验证的心理测量分数、临床诊断或疾病概率。该版本尚未完成有代表性的人类标注评测。

## 使用

将整个 `zh-emotion` 文件夹放入宿主支持的技能目录，保持 `SKILL.md` 与 `references/` 的相对位置。具体加载和自动发现方式以宿主说明为准；交付这个文件夹本身不等于已经安装或启用。

支持技能调用的宿主可尝试：

```text
使用 $zh-emotion 分析：“我不难过，这次调岗是我主动申请的，现在轻松多了。”
```

也可以明确提供上下文、目标句及格式：

```text
使用 zh-emotion，分析下面对话中甲最后一句，保留完整分析卡和歧义。
甲：你连续两次临时取消，我还专门请了假。
乙：反正我决定跟别人去了。
甲：行，你开心就好。
```

默认字段：原文与语境、手法、内容、效果、情绪、依据、综合判断、风险与歧义。综合判断沿用答题式连贯表达。上下文任务按需增加情绪进程；JSON 是可选格式，不是使用前提。

## 下游模型

把完整分析卡交给下游模型，尤其保留证据和风险字段。可使用这样的调用说明：

> 根据原文、分析卡和当前任务选择下一步回应。保持直接自述与推断的区别；涉及待定情绪时先确认或采用不依赖该推断的回应。不要将候选解释改写成用户已确认的体验。

研究或抑郁相关评估用途见 [交接约定](references/handoff.md)。该模块只提供线索；量表、临床阈值及构念映射需另行设计和验证。

## 相较本地 literary-zh-emo 原型的变化

- 保留答题式骨架和综合判断，扩展到自然对话与多种语境。
- 用证据性质和替代解释取代“真假情绪”的强制二分。
- 移除否认等于掩饰、按句式机械排列强度、每个判断必须两处证据等规则。
- 补充中性／未知、引用、角色身份、否定范围、时间、意图与情绪的区分。
- 重写为自拟示例，取消没有评分标准时保证满分的说法。
- 增加可选模型交接格式和可复用的合成试用案例。
