# 合成案例试用

这些案例检查可观察的分析行为，不是临床样本或独立人类标注集。评审允许多个合理读法，不按固定情绪词或句式判分。

## 运行方法

1. 固定宿主模型、技能版本、提示和上下文范围。先让模型读取 SKILL.md，再按需读取参考文件。
2. 将 cases.jsonl 中每个 input 独立提交，不把 checks 提前给模型。使用全新对话避免案例间污染。
3. 保存原始输出，按 checks 复核；重复运行时记录次数和设置。比较成对案例时单独检查上下文是否产生合理修正。
4. 同时用旧版本运行可比较改动；旧版与新版使用同一输入和模型。没有运行旧版就不报告提升百分比。

## 评审维度

| 维度 | 检查 |
|---|---|
| 主体与来源 | 是否把引用、角色、作者或读者混为输入者 |
| 命题完整性 | 是否保留否定、假设和时间 |
| 证据 | 引文是否存在，是否支撑具体结论 |
| 语境敏感性 | 同句在不同背景中是否合理调整，是否过度确定 |
| 输出可用性 | 手法、内容、效果／情感关系是否清楚，下游能否辨认推断 |
| 强度与未知 | 是否硬填数字、混淆表达与体验，是否允许未知 |

每项记录“满足／部分满足／不满足／不适用”及具体证据。仅当预先明确指标和样本分母时报告比例；不把合成案例通过率称为真实场景准确率。

## 当前验证边界

随本包交付的结构检查和少量独立模型试用，只能支持该版本能够加载并完成这些有限任务。它们不能证明情绪识别准确率、跨模型稳定性或心理测量效度。实际执行记录见压缩包旁的验证记录。
